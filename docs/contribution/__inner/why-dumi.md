在选用什么文档工具的标准上，主要考虑以下几点

- 不需要额外为其配置一套构建系统
- 支持 md 或 mdx
- monorepo 友好
- 支持 ts，最好能自动分析组件 API
- 可以编写可运行的代码示例，一定程度上可以充当开发时的 playground
- 不仅仅是组件库文档，支持未来其他类型的文档的建设

dumi 不能说都做到了，满足了我们的基本需求。且对于不能满足、做得一般的部分，至少看到了可扩展的空间。

除了 dumi 以外，还有几个文档构建工具

- [storybook](https://storybook.js.org/)
- [docz](https://www.docz.site/)

相对来说

`storybook` 不是以站点为概念的文档工具，更像一个 dashboard。理论上你可以将它和其他建站工具比如 `gastby` 等联合起来使用。就是比 `dumi` 更花功夫。
他的组件文档 + demo 的功能要比 dumi 的生成结果要更好一些。
但不支持 react 以外的框架。

`docz` 生态不太成熟，本身的功能也是三者中最缺乏的。

大家都不行的就是 API 文档的生成，基本都是依赖 `react-docgen-typescript`，这个插件对于复杂类型的描述差强人意。
